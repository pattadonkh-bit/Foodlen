# NutriKid (ชื่อภายในโค้ดและแพ็กเกจ: Foodlen) — ระบบเฝ้าระวังภาวะโภชนาการเด็กวัยเรียนจากภาพอาหารไทย

โครงงาน CS2569/SCS2-16 ตามเค้าโครง "การประเมินพลังงานและสารอาหารจากภาพอาหารไทยด้วยเทคนิค Deep Learning
เพื่อเฝ้าระวังภาวะโภชนาการของเด็กวัยเรียนบนเว็บแอปพลิเคชัน" (กลุ่มเป้าหมายเด็กอายุ 6–12 ปี)

## ระบบทำอะไร

1. ลงทะเบียนเด็ก (ต้องมีการยินยอมจากผู้ปกครอง) แล้วประเมินภาวะโภชนาการด้วย BMI-for-age (WHO 2007, z-score จากตาราง LMS)
2. ถ่าย/อัปโหลดภาพอาหาร → AI (ResNet50) จำแนกเมนูอาหารไทย
3. ถ้าความมั่นใจของ AI ต่ำกว่าเกณฑ์ (ค่าเริ่มต้น 0.80) ให้ผู้ใช้ยืนยัน/เลือกเมนูก่อน
4. ผู้ใช้เลือกสัดส่วนที่เด็กกิน (½, 1, 1½, 2) → ระบบคำนวณพลังงาน เทียบกับพลังงานอ้างอิงต่อวัน และประเมินด้วยฐานกฎ → ไฟจราจร + คำแนะนำ
5. บันทึกประวัติมื้อ และสรุปรายสัปดาห์ (พลังงานรายวัน ไฟจราจร ความครบของอาหาร 5 หมู่)
6. ระบบไม่เก็บไฟล์ภาพ; ลบข้อมูลเด็กได้จากหน้าเด็ก
7. กราฟและสถิติ (Chart.js ฝังไว้ในโปรเจกต์ ใช้ออฟไลน์ได้):
   - หน้าเด็ก: มาตรวัด z-score, กราฟ BMI ตามอายุเทียบเส้นเกณฑ์ WHO (−3, −2, +1, +2 SD), น้ำหนัก/ส่วนสูงตามเวลา
   - หน้าสรุปรายสัปดาห์: พลังงานรายวันเทียบเป้า, ไฟจราจรรายวัน, สัดส่วนไฟจราจร, อาหาร 5 หมู่
   - หน้าสถิติรวม (`/stats`): ภาวะโภชนาการของเด็กทั้งหมด, ไฟจราจร 14 วัน, เมนูยอดนิยม, ไฟจราจรแยกตามภาวะโภชนาการ, สัดส่วนที่ AI รับอัตโนมัติ/ผู้ใช้ยืนยัน

8. **ล็อกอินและแยกสิทธิ์** (Spring Security, รหัสผ่านแฮช BCrypt, เปิด CSRF):
   - **ผู้ปกครอง** สมัครเองที่ `/register` เห็นและแก้ได้เฉพาะเด็กที่ตัวเองลงทะเบียน (เด็กคนอื่นตอบ 404 เหมือนไม่มีอยู่) สถิติรวมนับเฉพาะเด็กของตัวเอง
   - **ครู/นักโภชนาการ** เห็นเด็กทุกคน และมีหน้า `/staff/class` สร้างบัญชีโดยผู้ดูแลระบบเท่านั้น (สมัครเองไม่ได้)
9. **แก้ไข/ลบ**: แก้ชื่อ เพศ วันเกิด ชั้น/ห้อง ของเด็ก, แก้/ลบการวัดน้ำหนักส่วนสูง, แก้/ลบมื้ออาหาร (แก้แล้วประเมินไฟจราจรใหม่), หน้า "ประวัติมื้ออาหาร" (200 มื้อล่าสุด)
10. **ภาพรวมสำหรับครู/นักโภชนาการ** (`/staff/class`): ตารางเด็กทั้งหมดเรียงตามความเสี่ยง ค้นหาชื่อ กรองตามชั้น/ห้อง ระดับความเสี่ยง ภาวะโภชนาการ
    และ "ไม่ได้บันทึกมื้อ ≥ 3 วัน" คลิกหัวตารางเพื่อเรียง ส่งออก CSV ได้ ระดับความเสี่ยง: **เสี่ยงสูง** = ผอมมาก/อ้วน หรือไฟแดง ≥ 50% ของมื้อใน 7 วัน,
    **เฝ้าระวัง** = ผอม/น้ำหนักเกิน หรือไฟแดง ≥ 30% (ต้องมีอย่างน้อย 3 มื้อ) — เกณฑ์เป็นค่าเริ่มต้นของผู้พัฒนา (`ClassOverviewService`) ยังไม่ผ่านผู้เชี่ยวชาญ

11. **ใช้งานง่ายขึ้น**: หน้าแรกเป็นแดชบอร์ด (การ์ดเด็กพร้อมปุ่ม "บันทึกมื้อ" และไฟจราจรของวันนี้), ตัวบอกขั้นตอนและเส้นทาง (breadcrumb) ในขั้นบันทึกมื้อ,
    ตัวเลือกเมนูแบบค้นหาพร้อมตัวกรองหมวด (ข้าว/เส้น, เนื้อสัตว์, เครื่องดื่ม, ผลไม้, ขนมหวาน, ของทอด) และสรุปพลังงานของมื้อที่เลือกแบบทันทีก่อนบันทึก,
    หน้าเด็กมีเมนูลัดไปแต่ละหัวข้อ และพับประวัติการวัด/ฟอร์มบันทึกไว้ (สคริปต์ที่ `static/js/app.js`)

12. **ถ่ายภาพจากกล้องในเบราว์เซอร์**: หน้าบันทึกมื้อมีปุ่ม "📷 เปิดกล้องถ่ายภาพ" (getUserMedia) ถ่ายแล้วย่อภาพให้ด้านยาวไม่เกิน 1280 px เป็น JPEG ส่งเข้าฟอร์มเดิม
    สลับกล้องหน้า/หลังได้บนมือถือ และยังมีปุ่ม "เลือกไฟล์ภาพ" เป็นทางเลือก **กล้องในเบราว์เซอร์ใช้ได้เฉพาะเมื่อเปิดเว็บผ่าน HTTPS หรือ localhost** (เปิดผ่าน http://<IP เครื่อง> จากมือถือ
    เบราว์เซอร์จะไม่ให้เปิดกล้อง เว็บจะแจ้งและให้ใช้ปุ่มเลือกไฟล์แทน) โค้ดอยู่ใน `static/js/app.js` (initCamera)

## โครงสร้าง

```
demo/
├── pom.xml, src/…              Spring Boot 4 (Java 17+) + Thymeleaf + Spring Data JPA + H2
│   ├── nutrition/              คำนวณ z-score และกลุ่มภาวะโภชนาการ (WHO)
│   ├── menu/, advice/          ตารางเมนู พลังงานอ้างอิง ฐานกฎคำแนะนำ
│   ├── domain/, service/       เด็ก การวัด มื้ออาหาร สรุปรายสัปดาห์ ตัวเรียก AI
│   ├── controller/             หน้าเว็บ
│   └── resources/
│       ├── who/                ตาราง WHO BMI-for-age (แปลงจากไฟล์ทางการของ WHO)
│       └── data/               menu_nutrition.csv, energy_targets.csv, recommendation_rules.psv  ← ให้ผู้เชี่ยวชาญตรวจ/แก้
└── yolo-service/               บริการ AI (Flask + PyTorch) จำแนกอาหารไทย 101 เมนู
    └── models/                 resnet50_thfood101.onnx (ใช้งาน, อยู่ใน git) + resnet50_thfood101.pt (ฝึกด้วย PyTorch ไม่อยู่ใน git) + classes_thfood101.json
    └── tools/                  export_thfood101.py (ส่งออกโมเดล + สร้างตารางเมนู), menu_seed_10menus.csv
```

(ชื่อโฟลเดอร์ `yolo-service` และคลาส `YoloService` คงไว้จากเดโมแรก แต่ตอนนี้ใช้โมเดล ResNet50 ไม่ใช่ YOLO)

## วิธีรัน

1. **บริการ AI** (พอร์ต 5000) ต้องมี Python 3.10–3.12 + PyTorch
   ```
   cd yolo-service
   py -3.10 -m venv .venv                                  # ครั้งแรกครั้งเดียว (Python 3.10-3.12 จาก python.org)
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   run-ai.bat                                               # หรือ .venv\Scripts\python.exe app.py
   ```
   (ถ้ารัน `python app.py` ตรงๆ แล้วขึ้นว่าขาด numpy/flask แปลว่า `python` ใน PATH เป็นตัวอื่นที่ไม่มีไลบรารี เช่นของ MSYS2 ให้ใช้ .venv ด้านบน)
   ต้องมีไฟล์ `yolo-service/models/resnet50_thfood101.onnx` (หรือ `.pt` ถ้าใช้ PyTorch; สร้างจากโปรเจกต์ทดลอง `food-nutrition-project`:
   `results/resnet50/best.pt`) ใช้ GPU อัตโนมัติถ้ามี หรือบังคับด้วย `FOODLEN_DEVICE=cpu`
2. **เว็บแอป** (พอร์ต 8080)
   ```
   cd demo
   ./mvnw spring-boot:run        # Windows: mvnw.cmd spring-boot:run
   ```
   เปิด http://localhost:8080 — ฐานข้อมูล H2 เก็บที่ `./data/` ถ้าไม่เปิดบริการ AI ยังบันทึกมื้อได้ด้วย "เลือกเมนูเอง"
3. ทดสอบ: `./mvnw test` — **หมายเหตุ: `WebFlowTest` ยังเป็นเวอร์ชันก่อนมีระบบล็อกอิน (เรียกหน้าเว็บโดยไม่ล็อกอิน) จึงจะล้มจนกว่าจะแก้ให้ล็อกอินก่อนเรียก**
   ส่วนทดสอบการคำนวณ z-score และฐานกฎไม่เกี่ยวกับล็อกอิน

### บัญชีผู้ใช้

ครั้งแรกที่เปิดต้องล็อกอิน ผู้ปกครองสมัครเองที่ `/register` โดยใช้อีเมลเป็นชื่อล็อกอิน (ไม่มีการส่งอีเมลยืนยัน) ส่วนบัญชีครู/นักโภชนาการสร้างตอนเปิดระบบด้วยตัวแปรสภาพแวดล้อม (ไม่เขียนรหัสผ่านลงไฟล์):
```
# PowerShell
$env:FOODLEN_BOOTSTRAP_STAFF_USERNAME = "อีเมลครู@example.com"
$env:FOODLEN_BOOTSTRAP_STAFF_PASSWORD = "รหัสผ่านอย่างน้อย 8 ตัว"
./mvnw spring-boot:run
```
ข้อมูลเด็กที่ลงทะเบียนไว้ก่อนมีระบบล็อกอินไม่มีเจ้าของ จะเห็นได้เฉพาะบัญชีครู/นักโภชนาการ

ดูหน้าตาและกราฟด้วยข้อมูลตัวอย่าง (เด็กสมมติ 4 คน + มื้ออาหาร 14 วัน ชื่อมี "(ตัวอย่าง)" ต่อท้าย) ทำงานเฉพาะเมื่อฐานข้อมูลยังว่าง
(ถ้าฐานข้อมูลเดิมมีเด็กอยู่แล้วจะสร้างเฉพาะบัญชีสาธิต ไม่สร้างเด็ก):
```
./mvnw spring-boot:run -Dspring-boot.run.arguments=--foodlen.seed-demo=true
```
โหมดนี้สร้างบัญชีสาธิต `teacher@foodlen.demo` (ครู), `parent1@foodlen.demo` (เจ้าของน้องมะลิและน้องต้นกล้า), `parent2@foodlen.demo` (เจ้าของน้องใบเตยและน้องภูมิ) ทุกบัญชีใช้รหัสผ่าน
`Foodlen#2569` (ค่าคงที่ `AccountBootstrap.DEMO_PASSWORD`) **ใช้เพื่อสาธิตเท่านั้น ห้ามเปิด seed-demo บนระบบที่มีข้อมูลจริง**
ล้างข้อมูลทั้งหมดโดยลบโฟลเดอร์ `demo/data/` ตอนปิดแอปแล้ว

ตั้งค่าใน `application.properties`: `foodlen.ai-service-url`, `foodlen.confidence-threshold`

## Deploy ฟรีบน Render + Neon (Postgres)

ใช้งานจริงอยู่ที่ <https://foodlen-web.onrender.com> โครงสร้าง: **เว็บ** (`foodlen-web`, Docker จาก `demo/Dockerfile`) + **บริการ AI** (`foodlen-ai`, Docker จาก `demo/yolo-service/Dockerfile`, ONNX บน CPU)
ทั้งสองเป็น Render web service แพ็กเกจ **free** + **ฐานข้อมูล** Neon Postgres แพ็กเกจ free ตั้งค่าไว้ใน `../render.yaml` (รากของ repo) Render เป็นผู้ build Docker ไม่ต้องลง Docker ในเครื่อง

**โมเดล ONNX**: บริการ AI ใช้ `yolo-service/models/resnet50_thfood101.onnx` (90 MB) แปลงจาก `.pt` ด้วย `python tools/export_onnx.py` ผลตรงกับ PyTorch
(ค่า logits ต่างกันไม่เกิน 3×10⁻⁶; ทดสอบ 10 ภาพจริง อันดับ 1 ตรงกันทั้งหมด) ใช้ RAM ราว 160–270 MB จึงอยู่ในแพ็กเกจฟรี 512 MB ได้

ขั้นตอน (ทำครั้งเดียว):
1. **Neon**: สร้างโปรเจกต์ Postgres (แพ็กเกจ Free) แล้วเก็บค่าจากหน้า Connect
   - `SPRING_DATASOURCE_URL` = `jdbc:postgresql://<host>/<database>?sslmode=require` (ขึ้นต้น `jdbc:postgresql://` ไม่ใช่ `postgresql://` และไม่ใส่ `channel_binding`)
   - `SPRING_DATASOURCE_USERNAME` และ `SPRING_DATASOURCE_PASSWORD` (แยกกัน ไม่ใส่ใน URL คัดลอกเฉพาะรหัสผ่าน ระวังช่องว่างหน้าหลัง)
2. **GitHub**: push โค้ดขึ้น repo (public) รวม `yolo-service/models/resnet50_thfood101.onnx` และ `classes_thfood101.json`
3. **Render**: New > Blueprint > ใส่ URL ของ repo (ช่อง Public Git Repository) > เลือก branch ที่มี `render.yaml` > กรอกค่าที่ขึ้น "Enter value":
   ค่า 3 อย่างจาก Neon, `FOODLEN_BOOTSTRAP_STAFF_USERNAME` (อีเมลครู), `FOODLEN_BOOTSTRAP_STAFF_PASSWORD` (อย่างน้อย 8 ตัว) และ
   `FOODLEN_AI_SERVICE_URL` (URL สาธารณะของบริการ AI เช่น `https://foodlen-ai.onrender.com` ถ้าชื่อซ้ำ Render จะต่อท้ายตัวอักษร ต้องใส่ให้ตรงกับที่อยู่จริง)
   แล้วกด Deploy Blueprint รหัสลับระหว่างเว็บกับ AI (`FOODLEN_AI_TOKEN`) Render สุ่มให้เอง
4. เปิดเว็บ ล็อกอินด้วยบัญชีครู ให้ผู้ปกครองสมัครที่ `/register` ตารางในฐานข้อมูลสร้างอัตโนมัติ (`ddl-auto=update`) เริ่มว่าง ไม่มีข้อมูลสาธิต
5. ถ้าเว็บไม่ขึ้น ดู Logs ของ `foodlen-web` บน Render (ค้นคำว่า `Caused by`) ปัญหาที่เคยเจอ: `password authentication failed` = รหัสผ่านฐานข้อมูลใน Environment ไม่ตรงกับ Neon

ข้อควรรู้:
- **ฟรีจริง**: บัญชี Render เป็นแพ็กเกจ Hobby ไม่มีบัตรเครดิตผูกอยู่ (ถ้าโควตาหมด บริการจะถูกระงับแทนการคิดเงิน) โควตาต่อเดือน: ชั่วโมงใช้งานฟรี 750 ชม., bandwidth 5 GB, นาที build 500 นาที ห้ามกด Add Card หรือ Upgrade ถ้าไม่ได้ตั้งใจจ่าย
- **หลับเมื่อว่าง**: ทั้งเว็บและ AI หลับหลังไม่มีคนเข้า 15 นาที ตื่นครั้งแรก ~50–60 วินาที (ครั้งแรกที่ส่งภาพอาจขึ้นว่า AI เชื่อมต่อไม่สำเร็จ ลองใหม่ใน 1 นาที หรือใช้ "เลือกเมนูเอง")
  **ก่อนพรีเซ็นต์ให้เปิดเว็บและลองส่งภาพล่วงหน้าสัก 5 นาที** ฐานข้อมูล Neon ฟรีก็หยุดพักเมื่อว่างเช่นกัน (ตื่นใน ~1 วินาที)
- **RAM 512 MB ของเว็บ (Java)** อาจตึง ตั้งค่า JVM ประหยัดไว้ใน `render.yaml` ถ้าเว็บล้มเพราะหน่วยความจำ ให้ดู Logs
- **บริการ AI เป็น URL สาธารณะ** จึงป้องกันด้วยรหัสลับ (`X-Foodlen-Token`): คำขอ `/predict` ที่ไม่มีรหัสถูกปฏิเสธ (401) แต่ไม่มีการจำกัดอัตราการเรียก
- **Blueprint ซิงก์อัตโนมัติ**: การแก้ `render.yaml` แล้ว push จะถูกซิงก์ไปที่ Render ทันที การเปลี่ยน *ชื่อ service* จะสร้าง service ใหม่ (ที่อยู่เว็บเปลี่ยน และต้องกรอกค่าลับใหม่) จึงไม่ควรเปลี่ยนชื่อโดยไม่ตั้งใจ
- Render ให้ HTTPS อยู่แล้ว (ตั้งคุกกี้เป็น Secure) กล้องในเบราว์เซอร์จึงใช้ได้ — **ก่อนใช้กับข้อมูลเด็กจริงยังต้องทบทวนด้านความปลอดภัยและ PDPA** (เซิร์ฟเวอร์อยู่ในสิงคโปร์)
- Hugging Face Docker Space ใช้ฟรีไม่ได้ (เป็นแพ็กเกจ Paid) ไฟล์ใน `../huggingface/` จึงไม่ได้ใช้ เก็บไว้เป็นตัวอย่าง
- โมเดลฝึกจากชุดข้อมูล THFOOD-100 (อนุญาตเฉพาะงานวิจัย/การศึกษาที่ไม่ใช่เชิงพาณิชย์) ใช้เพื่องานโครงงานเท่านั้น และ repo นี้เป็น public

## สิ่งที่ยังเป็นค่าสาธิต (ต้องตรวจสอบก่อนใช้จริง)

- **ตารางโภชนาการเมนู** (`menu_nutrition.csv`): ทั้ง 101 เมนูมีพลังงานแล้ว แต่ **มีสองระดับความน่าเชื่อถือ** (ดูช่อง `status`)
  - `provisional` 62 เมนู: แถวที่ตรงชื่อในตารางแคลอรี่อาหารของ hdmall.co.th ซึ่งอ้างฐานข้อมูลสถาบันโภชนาการ มหิดล (แหล่งทุติยภูมิ ค่าประมาณต่อหน่วย
    ไม่ใช่ Thai FCD ต้นฉบับ) สคริปต์ `yolo-service/tools/fill_energy_from_table.py` รายการแถวที่ใช้ใน `energy_rows_used.csv`
  - `estimated` 39 เมนู: **ผู้พัฒนาประมาณเอง** จากเมนูที่คล้ายกันในตารางเดียวกัน (เช่น หมูฮ้อง ≈ พะโล้) หรือจากค่าต่อ 100 กรัม × น้ำหนักที่สมมติ
    (เช่น ก๋วยจั๊บ 400 กรัม) หรือผลรวมหลายส่วน (ข้าวเหนียวมะม่วง = ข้าวเหนียวมูน + มะม่วงครึ่งลูก) สคริปต์ `fill_estimates.py` วิธีคำนวณรายเมนูใน
    `energy_estimates.csv` หน้าผลประเมินจะแจ้งผู้ใช้ว่าเป็นค่าประมาณ **ค่ากลุ่มนี้ไม่ใช่ข้อมูลที่ตรวจสอบแล้ว ผู้เชี่ยวชาญต้องตรวจก่อนใช้จริง**
  - ข้อควรระวังอื่น: เมนูที่ชุดข้อมูลตั้งชื่อกว้างกว่าแถวในตารางใช้แถวตัวแทน (แกงจืด = แกงจืดตำลึงหมูสับ) ส้มตำในตารางมีหลายสูตร (35–118 kcal)
    ใช้ 80 kcal; บางเมนูหน่วยบริโภคเล็ก (1 ชิ้น 1 ฟอง 1 ทัพพี) ต้องเลือกจำนวนหน่วยที่กินจริง (เลือกได้ ½–5 รับได้ถึง 10)
  - โปรตีน/ไขมัน/คาร์โบไฮเดรต (ครบ 101 เมนู) **ผู้พัฒนาคำนวณเอง** ไม่ใช่ค่าที่วัดหรือค่าทางการ: เลือกแถวป้าย INMU (ต่อ 100 กรัม) ที่คล้ายเมนู
    แล้วใช้สัดส่วนสารอาหารต่อกิโลแคลอรีของแถวนั้นปรับให้ได้พลังงานเท่าค่าของเมนู (สคริปต์ `yolo-service/tools/fill_macros.py` แถวที่ใช้ของแต่ละเมนูใน
    `macro_estimates.csv`) เมนูที่ไม่มีแถวตรงตัวใช้แถวตัวแทนหรือผสมวัตถุดิบ (เช่น ผัดฉ่า = ปลาหมึกสด 40% + ผัดเผ็ดไก่ 60% ของพลังงาน)
    แถว "ผัดเผ็ดถั่วฝักยาว" ในตารางมีโปรตีนสูงผิดปกติจึงไม่ใช้ ยังไม่ได้เทียบกับ Thai FCD ต้นฉบับ และยังไม่มีค่าน้ำตาล/ใยอาหาร/โซเดียมในเว็บ
  - **เมนูเพิ่มเติม 110 เมนู** (รวมเป็น 211) สำหรับ "เลือกเอง" เท่านั้น **ไม่มีใน AI** (AI จำแนกได้ 101 เมนูเดิม เพราะไม่มีภาพฝึกของเมนูใหม่): นมและเครื่องดื่ม 20, ผลไม้ 13,
    ไข่/เนื้อสัตว์ 10, อาหารจานหลักที่เด็กกินบ่อย 30, ฟาสต์ฟู้ด/เบเกอรี่ 11, ขนมและของว่าง 26 เพิ่มด้วย `yolo-service/tools/add_menus.py` (รายละเอียดการคำนวณรายเมนูใน `new_menus.csv`)
    พลังงานจากแถวเมนูของตารางแคลอรี่ (`provisional` 1 หน่วยบริโภคตามที่ตารางระบุ) หรือค่าต่อ 100 กรัม/มล. × ปริมาณที่ผู้พัฒนาสมมติ (`estimated` ระบุปริมาณในช่องหน่วยบริโภค เช่น นม 200 มล.)
    สารอาหารคำนวณด้วยวิธีเดียวกับเมนูเดิม และใส่ **น้ำตาล** (แสดงในหน้าผลประเมิน) เฉพาะที่ข้อมูลต้นทางมีและสมเหตุสมผล (ข้ามแถวที่น้ำตาลมากกว่าคาร์โบไฮเดรต) เมนูหวานติดแท็ก `sweet`
    ซึ่งกฎคำแนะนำจะเตือน — ผู้เชี่ยวชาญควรตรวจก่อนใช้จริง ตารางแคลอรี่บางแถวมีค่าผิดปกติ (เช่น ปลาช่อนทอด 1,840 kcal) จึงเลือกเฉพาะแถวที่สมเหตุสมผลและไม่ได้ใช้ทุกแถว
  - tag ทอดและหมู่อาหารของเมนูใหม่กำหนดจากคำในชื่อเมนูอัตโนมัติ (เบื้องต้น) ผู้เชี่ยวชาญควรตรวจ
- **พลังงานอ้างอิงต่อวัน** (`energy_targets.csv`): 6–8 ปี 1,400, ชาย 9–12 ปี 1,700, หญิง 9–12 ปี 1,600 kcal จากเอกสารคำนวณอาหารโรงเรียน (แหล่งทุติยภูมิ) → ควรตรวจกับ Thai DRI 2563
- **ฐานกฎคำแนะนำ** (`recommendation_rules.psv`): เกณฑ์สัดส่วนพลังงานต่อมื้อ (เช่น มื้อหลักไม่เกิน 33%/40% สำหรับเด็กน้ำหนักเกิน) เป็นค่าเริ่มต้นของผู้พัฒนา ยังไม่ผ่านผู้เชี่ยวชาญ
- **tag และหมู่อาหารของเมนู**: การจัดกลุ่มเป็นการตัดสินใจเบื้องต้น
- **เกณฑ์การเจริญเติบโต**: ใช้ WHO 2007 (BMI-for-age) ซึ่งอาจต่างจากเกณฑ์ที่กรมอนามัยใช้ (ฉบับปี 2564)
- **AI รองรับ 101 เมนู** (THFOOD-100 + ข้าวเหนียวมะม่วง) ResNet50 test accuracy 92.30%, top-5 99.09%, macro-F1 0.893 บนชุดทดสอบ 13,433 ภาพของผู้เขียนชุดข้อมูล (ฝึกครั้งเดียว; รหัสในชื่อไฟล์ภาพเดียวกันปรากฏทั้งชุดฝึกและทดสอบ จึงอาจสูงกว่าของจริงกับร้านที่ไม่เคยเห็น) ยังไม่มีเมนูเด็กที่เกี่ยวกับน้ำตาล เช่น น้ำหวาน ขนม นมกล่อง ที่ THFOOD-100 มีแต่อาหารจานหลักของร้านอาหาร
- **ระบบล็อกอินยังเป็นแบบพื้นฐาน**: ไม่มีการกู้รหัสผ่าน/เปลี่ยนรหัสผ่านในหน้าเว็บ ไม่มีจำกัดจำนวนครั้งที่ล็อกอินผิด ไม่มีหน้าจัดการผู้ใช้ (บัญชีครูสร้างตอนเปิดระบบเท่านั้น)
  และยังไม่ผ่านการตรวจความปลอดภัยโดยผู้เชี่ยวชาญ ควรใช้ HTTPS เมื่อใช้งานจริง — **ก่อนใช้กับข้อมูลเด็กจริงต้องทบทวนด้านความปลอดภัยและ PDPA**
